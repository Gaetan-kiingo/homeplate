### Findings from the previous run that no longer reproduce

`IT3-F1` (promote re-enqueue losing a promotion on an unchanged `scheduled_start`) — fixed:
`lifecycle.securePromotionSchedule` detects a dedupe onto the delivering row and secures a fresh
one, and the handler passes `ctx.jobId` through. `ADRC-W3-01` (timezone-dependent `localDate` on
the wire) — fixed by `serializers.isoCalendarDate`; only the audit-log residual W3-F2 remains.
`IT3-F2` / `ADRC-W3-02` (lint) — `npm run lint` is clean. `COV-W3-02` (dead `listings/repo.toListing`
export) — now exercised by `tests/coverage/coverage-lane.test.js`. `COV-W3-07` — `.eslintignore`
is anchored to `/coverage/`. `TCB-01` / `ADRC-W3-03` (weekly-cap anchor) is **not a defect but a
spec ambiguity**: ADR-009 fixes 60 meals/week without naming the window shape; the code implements
a Monday-anchored LA calendar week and `requirements-inventory.json` now states that reading
explicitly. The SRS is silent; a rolling 7-day window is the stricter alternative. Team decision at
CDR, not an agent's.
