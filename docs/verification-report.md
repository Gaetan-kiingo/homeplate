### F-1 (minor, test infrastructure) — Concurrent jest invocations share one test database and corrupt each other
*Consolidates TCB-02, MTQ-04, COV-06, ADRCONF-F02.* **Requirement:** none (verification reliability; NFR-02 signal quality).
**Reproduction:** run two jest processes against the default `homeplate_test` DB / Redis DB 1 concurrently — each `globalSetup` drops/reseeds the schema under the other's live queries. Observed repeatedly during multi-lane verification: wandering failure sets (13–16 failures that change between runs), a `deadlock detected` in `DROP SCHEMA`, a >600 s globalSetup hang, and a foreign worker delivering another test's outbox job.
**Current state:** `tests/helpers/globalSetup.js` still has no cross-process guard (no advisory lock). The `TEST_DATABASE_URL` / `TEST_REDIS_URL` / `OBJECT_STORAGE_BUCKET` overrides are honoured and proven to give clean isolation.
**Proposed fix:** take `pg_advisory_lock(hashtext('homeplate_test_suite'))` in globalSetup (release in globalTeardown) so runs serialize, or derive per-run DB/Redis/bucket names; at minimum document that concurrent lanes MUST set the overrides.
**Why still open:** does not affect a single-runner CI (two consecutive solo runs green, 611/611); fix is test-infra hardening the team should land before the next multi-lane verification round.

### F-2 (minor, test) — `bootstrap.test.js` hardcodes the Redis DB index, defeating the documented override
*COV-07.* **Requirement:** none.
**Reproduction:** run the suite with `TEST_REDIS_URL=redis://localhost:6379/5` → `tests/unit/bootstrap.test.js:73` fails: `expect(process.env.REDIS_URL).toMatch(/\/1$/)`.
**Proposed fix:** assert isolation, not the literal default — parse the URL and require a non-dev index (`!== 0`) instead of exactly `/1`.
**Why still open:** invisible on the default environment (passes there); only bites the F-1 workaround. Fix alongside F-1.
